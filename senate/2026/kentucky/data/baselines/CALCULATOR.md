# Offline conditional calculator

Run `python scripts/calculator.py fixtures/counted-fixed-final-denominator.input.json` from this directory. The CLI takes one UTF-8 JSON file, prints one strict JSON object, returns 0 for valid conditional scenarios or 2 for expected invalid input, and keeps stderr empty. It performs no network requests or polling.

Input fields are `mode` (`historical` or `live`), distinct two-name `pair` (A thenB), distinct `others` identities, `other_scope` (`named` or `unresolved`), a nonblank `assumptions` label, finite fractional pair-margin `target` in[-1,1], optional exact `selected_unit`, and a nonempty `units` list. Unsupported settings/fields fail. Every unit has a globally unique nonblank string `key`, `counted:{A,B,other:{identity:count}}`, `remaining`, `participation`, `share` and `other_allocation:{identity:fraction}`. Candidate/object collisions, unknown identities and duplicate JSON fields fail rather than overwrite.

`remaining` means a stipulated number of **uncounted all-candidate contest votes**, not registered persons, issued ballots or precinct percentages. Counted votes are finite/nonnegative and fixed. `participation` in[0,1] allocates the remaining pool between A+B and other choices. `share` in[0,1] is A's share of the remaining pair pool; null explicitly means unknown. Positive other pools require balanced explicitly supplied allocations across all named/container identities. Every supplied allocation is validated, even when its volume is zero. Optional `counted_total` must equal the complete supplied field, never be smaller than pair counts. Historical mode requires counted votes zero. All units/targets/settings are validated before unknown/no-pool/selection returns, including overflow. Whitespace only tests key blankness; exact identifier strings are preserved.

For unit u, remaining pair votes are `P_u=remaining_u*participation_u`. Final A is countedA plus `sum(P_u*q_u)`; final B is countedB plus `sum(P_u*(1-q_u))`. Other candidates retain countedOther plus their explicitly allocated remaining nonpair pool. Final pair denominator includes countedA+countedB+allremaining pair votes; final all-candidate denominator includes every counted candidate and the **whole** remaining pool. A positive-pair-pool null preference returns unknown. A zero-pair preference remains undefined rather than 0.5. No-positive-pool/no-positive-pair-pool and fixed-target status are separately reported.

At fixed historical pair weights, an unbounded common A-share shift ties at `(B-A)/(2*(A+B))`; a target pair margin m adds m/2. A+1 means m=.01 and therefore 0.5 additional A-share percentage points. One A-share point produces two pair-margin points and `.02*pair_volume` net votes. The calculator also solves a clipped common shift with each `q_u+shift` bounded to[0,1]. It retains unbounded algebra, clipping, feasible-root residuals, bounded secured/impossible cases, weights and unit contributions. Live uniform shifts apply only to remaining preferences; counted votes stay fixed.

Selected-only calculations solve one selected remaining A share while every other unit retains its explicitly supplied assumption. Unknown positive-pool other units keep the result unknown. Raw required shares below 0/above 1 remain secured/impossible, with a separate feasible clipped endpoint. The selected-only formula is `(target*final_pair - fixed_net + selected_pair_pool)/(2*selected_pair_pool)`. No selected pair pool produces a separate no-pool fixed-target result.

A pair leader can lose to another named candidate. The output separately reports baseline full-field strict A plurality over the complete supplied candidate field, or unresolved identity status. A pair tie/A+1 and this conditional plurality check do not certify the legal result. Current final ballot mapping, eligible write-in identities and applicable rules require final official publications; historical tickets, old IDs and primary nominees are insufficient. Fractional expected votes are deterministic illustrations, not probabilities or integer certified counts.

The 47 actual CLI fixtures include counted-fixed/final denominators, unknown preferences, no pool, negative/>1 selected shares, unknown-other selected-only, clipping distinct from unbounded algebra, undefined zero pair, pair leader losing the full field, global invalid keys in early-return branches, invalid target/count/share/pool/allocation/setting/identity/object fields and overflow. Each stores the exact input/stdout/exit/stderr. Independent rational affine-segment checks verify all 20 historical scenario roots and every contribution/weight. See [validation](proof/calculator-validation.json).

The feasible pair target also reports the complete supplied candidate field, its all-candidate A share and pair net over the all-candidate denominator. The selected-only output separately gives the strict full-field plurality boundary when all other supplied candidate allocations are known; a feasible pair target can still be impossible against another named candidate. Equality at the boundary is not strict plurality. Pair-target totals use the target denominator identity, keeping numerical root residuals separate so a floating-point tie cannot become a false lead.
